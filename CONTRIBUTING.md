## Кодекс поведения

Участвуя в этом проекте, вы соглашаетесь соблюдать наш кодекс поведения:

- Будьте уважительны к другим участникам
- Принимайте конструктивную критику
- Фокусируйтесь на том, что лучше для сообщества
- Проявляйте эмпатию к другим участникам

## Как я могу помочь?

### Сообщения об ошибках

Если вы нашли ошибку:

1. Проверьте, не была ли она уже сообщена в [Issues](https://github.com/homeserver-os/issues)
2. Если нет, создайте новый issue с подробным описанием:
   - Версия системы
   - Шаги для воспроизведения
   - Ожидаемое поведение
   - Фактическое поведение
   - Логи (если применимо)

### Предложения новых функций

1. Создайте issue с меткой `enhancement`
2. Опишите предлагаемую функцию
3. Объясните, почему она будет полезна
4. Предложите возможную реализацию

### Исправление ошибок и добавление функций

1. Найдите issue, над которым хотите работать
2. Оставьте комментарий, что берете его в работу
3. Следуйте процессу разработки (см. ниже)

## Процесс разработки

### 1. Форк и клонирование

```bash
# Форкните репозиторий на GitHub
# Затем клонируйте свой форк
git clone https://github.com/ваш-username/homeserver-os.git
cd homeserver-os

# Добавьте upstream репозиторий
git remote add upstream https://github.com/homeserver-os/homeserver-os.git
```

### 2. Создание ветки

```bash
# Обновите main ветку
git checkout main
git pull upstream main

# Создайте новую ветку для вашей работы
git checkout -b feature/название-функции
# или
git checkout -b fix/название-бага
```

### 3. Разработка

- Пишите чистый, читаемый код
- Следуйте стандартам кода проекта
- Добавляйте комментарии где необходимо
- Пишите тесты для новой функциональности

### 4. Тестирование

```bash
# Запустите все тесты
cd tests
./run_tests.sh

# Соберите проект
cd ..
make clean
make all

# Протестируйте в QEMU
make run
```

### 5. Коммит изменений

```bash
# Добавьте изменения
git add .

# Создайте коммит с осмысленным сообщением
git commit -m "feat: добавлена поддержка IPv6"
```

### 6. Push и Pull Request

```bash
# Отправьте изменения в свой форк
git push origin feature/название-функции
```

Затем:
1. Перейдите на GitHub
2. Создайте Pull Request из вашей ветки в main ветку upstream
3. Заполните шаблон PR
4. Дождитесь ревью

## Стандарты кода

### C код

```c
// Используйте snake_case для функций и переменных
void my_function(int parameter_name) {
    int local_variable = 0;
}

// Используйте UPPER_CASE для констант
#define MAX_BUFFER_SIZE 1024

// Используйте typedef для структур
typedef struct {
    uint32_t id;
    char name[64];
} my_struct_t;

// Комментарии для функций
/*
 * Краткое описание функции
 * 
 * @param param1 Описание параметра
 * @return Описание возвращаемого значения
 */
int my_function(int param1);
```

### Форматирование

- Отступы: 4 пробела (не табы)
- Максимальная длина строки: 100 символов
- Открывающая скобка на той же строке
- Пробелы вокруг операторов

```c
// Хорошо
if (condition) {
    do_something();
}

// Плохо
if(condition){
do_something();
}
```

### Именование файлов

- Используйте lowercase с подчеркиваниями
- `.c` для исходных файлов
- `.h` для заголовочных файлов

Примеры:
- `memory_manager.c`
- `network_stack.h`

## Тестирование

### Написание тестов

Создайте тестовый файл в `tests/`:

```bash
#!/bin/bash
# test_memory.sh

echo "Testing memory manager..."

# Ваши тесты здесь
if [ условие ]; then
    echo "PASS: Memory allocation works"
else
    echo "FAIL: Memory allocation failed"
    exit 1
fi
```

### Запуск тестов

```bash
# Все тесты
cd tests
./run_tests.sh

# Конкретный тест
./test_memory.sh
```

## Документация

### Комментарии в коде

- Комментируйте сложную логику
- Объясняйте "почему", а не "что"
- Используйте английский язык для комментариев в коде

```c
// Плохо
// Увеличиваем счетчик
counter++;

// Хорошо
// Increment counter to track number of failed login attempts
// After 5 attempts, the account will be locked
counter++;
```

### Документация API

Обновляйте `docs/technical.md` при добавлении новых API:

```markdown
### Новая функция

Описание функции.

**API:**
```c
int new_function(int param);
```

**Параметры:**
- `param` - описание параметра

**Возвращает:**
- `0` при успехе
- `-1` при ошибке
```

### Пользовательская документация

Обновляйте `docs/user-guide.md` для новых функций, видимых пользователю.

## Сообщения коммитов

Используйте [Conventional Commits](https://www.conventionalcommits.org/):

### Формат

```
<тип>(<область>): <описание>

[необязательное тело]

[необязательный футер]
```

### Типы

- `feat` - новая функция
- `fix` - исправление бага
- `docs` - изменения в документации
- `style` - форматирование, отсутствующие точки с запятой и т.д.
- `refactor` - рефакторинг кода
- `test` - добавление тестов
- `chore` - обновление задач сборки, конфигов и т.д.

### Примеры

```bash
feat(network): добавлена поддержка IPv6

fix(memory): исправлена утечка памяти в kmalloc

docs(api): обновлена документация REST API

test(scheduler): добавлены тесты для планировщика

refactor(fs): упрощена логика выделения блоков
```

## Процесс ревью

### Что проверяют ревьюеры

- Соответствие стандартам кода
- Наличие тестов
- Обновление документации
- Отсутствие регрессий
- Производительность
- Безопасность

### Как ускорить ревью

- Делайте небольшие, сфокусированные PR
- Пишите понятные описания PR
- Отвечайте на комментарии быстро
- Будьте открыты к предложениям
