# Часто задаваемые вопросы (FAQ)

## Общие вопросы

### Что такое Home Server OS?

Home Server OS - это специализированная операционная система, разработанная для домашних серверов. Она предоставляет простой веб-интерфейс для управления сервером, поддержку виртуализации, автоматическое резервное копирование и встроенные средства безопасности.

### Для кого предназначена эта ОС?

- Домашние пользователи, желающие создать собственный сервер
- Энтузиасты self-hosting
- Разработчики, нуждающиеся в тестовой среде
- Студенты, изучающие системное программирование
- Малый бизнес для локальных серверов

### Какая лицензия используется?

Home Server OS распространяется под лицензией MIT, что означает свободное использование, модификацию и распространение.

### Стабильна ли система?

Текущая версия (0.1.0) находится в стадии Alpha. Система функциональна, но не рекомендуется для критически важных задач. Используйте на свой риск.

## Установка и настройка

### Какие системные требования?

**Минимальные:**
- Процессор: x86_64 (64-bit)
- RAM: 512 MB
- Диск: 4 GB
- Сеть: Ethernet

**Рекомендуемые:**
- Процессор: 2+ ядра x86_64
- RAM: 4 GB+
- Диск: 100 GB+
- Сеть: Gigabit Ethernet

### Можно ли установить на виртуальную машину?

Да! Home Server OS отлично работает в VirtualBox, VMware, QEMU и других гипервизорах.

### Как изменить порт веб-интерфейса?

Отредактируйте файл `/etc/system.conf`:
```ini
[services]
web_admin_port = 8080  # Измените на нужный порт
```

Затем перезапустите веб-сервис:
```bash
service restart web
```

### Как сбросить пароль администратора?

1. Загрузитесь в режиме восстановления
2. Выполните команду:
   ```bash
   passwd admin
   ```
3. Введите новый пароль
4. Перезагрузите систему

### Поддерживается ли UEFI?

Да, система поддерживает как BIOS, так и UEFI загрузку.

## Функциональность

### Сколько контейнеров можно запустить одновременно?

По умолчанию максимум 10 контейнеров. Это ограничение можно изменить в настройках виртуализации.

### Сколько виртуальных машин поддерживается?

По умолчанию максимум 5 виртуальных машин. Лимит настраивается в конфигурации.

### Поддерживается ли Docker?

В текущей версии (0.1.0) Docker не поддерживается. Система использует собственную реализацию контейнеров. Поддержка Docker планируется в версии 0.2.0.

### Можно ли использовать внешние диски?

Да, система автоматически определяет подключенные USB и SATA диски. Вы можете монтировать их через веб-интерфейс или командную строку.

### Поддерживается ли RAID?

Да, поддерживаются RAID уровни 0, 1, 5 и 10. Настройка доступна через веб-интерфейс в разделе "Хранилище".

### Как работает автоматическое резервное копирование?

По умолчанию система создает ежедневные инкрементальные бэкапы и хранит их 7 дней. Настройки можно изменить в разделе "Резервное копирование".

### Поддерживается ли IPv6?

В текущей версии поддерживается только IPv4. Поддержка IPv6 планируется в версии 0.3.0.

## Безопасность

### Насколько безопасна система?

Система включает базовые средства безопасности:
- Firewall с фильтрацией пакетов
- Аутентификация пользователей
- SSH с настраиваемыми параметрами
- Блокировка после неудачных попыток входа

Однако, как Alpha версия, система может содержать уязвимости. Не используйте для критически важных данных.

### Как настроить firewall?

Через веб-интерфейс:
1. Перейдите в "Безопасность" → "Firewall"
2. Добавьте правила для нужных портов
3. Сохраните изменения

Через командную строку:
```bash
firewall add --action allow --protocol tcp --port 80
```

### Шифруются ли данные?

В текущей версии шифрование дисков не реализовано. Эта функция планируется в будущих версиях.

### Как обновить систему?

```bash
system update
```

Или через веб-интерфейс: "Система" → "Обновления"

**Примечание:** Автоматические обновления пока не реализованы.

## Сеть

### Как настроить статический IP?

Отредактируйте `/etc/network.conf`:
```ini
[network]
interface = eth0
dhcp = false
ip_address = 192.168.1.100
netmask = 255.255.255.0
gateway = 192.168.1.1
dns_servers = 8.8.8.8,8.8.4.4
```

Перезапустите сетевой сервис:
```bash
service restart network
```

### Поддерживается ли Wi-Fi?

В текущей версии поддерживается только Ethernet. Поддержка Wi-Fi планируется в будущих версиях.

### Как открыть порт в firewall?

```bash
firewall add --action allow --protocol tcp --port 3000 --description "My App"
```

### Можно ли настроить VPN?

VPN не встроен в систему, но вы можете запустить VPN-сервер в контейнере или виртуальной машине.

## Виртуализация

### В чем разница между контейнерами и VM?

**Контейнеры:**
- Легковесные
- Быстрый запуск
- Разделяют ядро с хостом
- Меньше изоляции

**Виртуальные машины:**
- Полная изоляция
- Собственное ядро
- Больше ресурсов
- Медленнее запускаются

### Как создать контейнер?

Через веб-интерфейс:
1. "Виртуализация" → "Контейнеры"
2. "Создать контейнер"
3. Заполните параметры
4. Нажмите "Создать"

Через API:
```bash
curl -X POST http://localhost:8081/api/containers \
  -H "Content-Type: application/json" \
  -d '{"name":"my-app","image":"nginx","cpu_limit":50,"memory_limit":512}'
```

### Можно ли мигрировать VM между серверами?

В текущей версии миграция не поддерживается. Эта функция планируется в будущих версиях.

## Производительность

### Сколько RAM нужно для нормальной работы?

Минимум 512 MB, но рекомендуется 4 GB или больше, особенно если планируете запускать контейнеры или VM.

### Как оптимизировать производительность?

1. Выделите достаточно RAM
2. Используйте SSD вместо HDD
3. Ограничьте количество одновременно работающих контейнеров/VM
4. Настройте лимиты ресурсов для контейнеров
5. Регулярно очищайте старые бэкапы

### Поддерживается ли многоядерность?

Да, система поддерживает многоядерные процессоры и эффективно распределяет нагрузку.

1. Создайте файл в `drivers/`
2. Реализуйте необходимые функции
3. Добавьте в систему инициализации
4. Обновите документацию

Полная документация API находится в [docs/technical.md](docs/technical.md).

## Устранение неполадок

### Система не загружается

1. Проверьте, что BIOS/UEFI настроен правильно
2. Загрузитесь в режиме восстановления
3. Проверьте логи: `/var/log/system.log`
4. Попробуйте восстановить из бэкапа

### Нет доступа к веб-интерфейсу

1. Проверьте, что веб-сервис запущен:
   ```bash
   service status web
   ```

2. Проверьте firewall:
   ```bash
   firewall list | grep 8080
   ```

3. Проверьте IP адрес:
   ```bash
   ip addr show
   ```

### Контейнер не запускается

1. Проверьте логи:
   ```bash
   container logs <id>
   ```

2. Проверьте лимиты ресурсов
3. Убедитесь, что не достигнут лимит контейнеров
4. Перезапустите контейнер

### Высокая загрузка CPU

1. Проверьте процессы:
   ```bash
   top
   ```

2. Проверьте запущенные контейнеры/VM
3. Ограничьте ресурсы для контейнеров
4. Проверьте логи на наличие ошибок

### Заканчивается место на диске

1. Проверьте использование:
   ```bash
   df -h
   ```

2. Удалите старые бэкапы
3. Очистите логи
4. Удалите неиспользуемые контейнеры
