# Варианты изоляции проекта Home Server OS

Дата: 2026-05-07
Цель: Изолировать разработку ОС от основной Windows системы

## Проблема

Разработка операционной системы требует:
- Компиляции большого количества кода
- Модификации системных файлов
- Тестирования низкоуровневых компонентов
- Работы с загрузчиками и образами дисков

Все это может повредить основную Windows систему.

## Варианты изоляции

### Вариант 1: WSL2 (Windows Subsystem for Linux) ⭐ РЕКОМЕНДУЕТСЯ

**Преимущества:**
- Встроено в Windows 10/11
- Полноценная Linux среда
- Изолировано от Windows
- Быстрая работа
- Доступ к файлам Windows и Linux
- Нативная компиляция Linux кода

**Недостатки:**
- Требует включения виртуализации
- Занимает место на диске (~2-5 GB)

**Установка:**
```powershell
# В PowerShell от администратора:
wsl --install -d Ubuntu-22.04

# После перезагрузки:
wsl --set-default-version 2
```

**Использование:**
```bash
# Запуск WSL
wsl

# Доступ к проекту из WSL
cd /mnt/c/NewProject

# Работа с ядром
cd /mnt/c/core/linux-6.12.28
make menuconfig
```

### Вариант 2: Docker Desktop

**Преимущества:**
- Полная изоляция в контейнерах
- Легко создавать/удалять среды
- Не влияет на Windows
- Можно использовать готовые образы для сборки

**Недостатки:**
- Требует Docker Desktop
- Больше накладных расходов
- Сложнее для новичков

**Установка:**
1. Скачать Docker Desktop: https://www.docker.com/products/docker-desktop/
2. Установить и запустить

**Использование:**
```bash
# Создать контейнер для сборки
docker run -it -v C:\NewProject:/project ubuntu:22.04 bash

# Внутри контейнера
cd /project
apt update && apt install build-essential
```

---

### Вариант 3: VirtualBox VM

**Преимущества:**
- Полная изоляция (отдельная виртуальная машина)
- Можно тестировать загрузку ОС
- Полный контроль над виртуальным железом
- Безопасно для Windows

**Недостатки:**
- Медленнее WSL2
- Требует больше ресурсов (RAM, CPU)
- Занимает много места (20+ GB)

**Установка:**
1. Скачать VirtualBox: https://www.virtualbox.org/
2. Создать VM с Ubuntu 22.04
3. Выделить ресурсы: 4+ GB RAM, 2+ CPU, 50+ GB диск

**Использование:**
- Работать внутри VM
- Использовать Shared Folders для доступа к C:\NewProject

---

### Вариант 4: MSYS2/MinGW (НЕ рекомендуется)

**Преимущества:**
- Не требует виртуализации
- Легкий

**Недостатки:**
- Ограниченная совместимость с Linux кодом
- Сложности с компиляцией ядра
- Не полная изоляция
- Может конфликтовать с Windows

## Рекомендация: WSL2

Для вашего случая **WSL2** - лучший выбор:

### Почему WSL2?

1. ✅ **Полная изоляция** - Linux работает в отдельной VM
2. ✅ **Безопасно для Windows** - не может повредить систему
3. ✅ **Нативная компиляция** - Linux код компилируется как на настоящем Linux
4. ✅ **Быстро** - почти нативная производительность
5. ✅ **Удобно** - доступ к файлам Windows через /mnt/c/
6. ✅ **Бесплатно** - встроено в Windows

### План действий с WSL2

#### Шаг 1: Установка WSL2 (5 минут)

```powershell
# PowerShell от администратора
wsl --install -d Ubuntu-22.04
```

Перезагрузите компьютер.

#### Шаг 2: Первый запуск (2 минуты)

```powershell
# После перезагрузки
wsl
```

Создайте пользователя и пароль.

#### Шаг 3: Установка инструментов (5 минут)

```bash
# Внутри WSL
sudo apt update
sudo apt install -y build-essential git vim nano \
    libncurses-dev flex bison libssl-dev libelf-dev \
    bc python3 python3-pip qemu-system-x86
```

#### Шаг 4: Настройка проекта (2 минуты)

```bash
# Создать символическую ссылку на проект
ln -s /mnt/c/NewProject ~/homeserver-os
ln -s /mnt/c/core/linux-6.12.28 ~/linux-kernel

# Перейти в проект
cd ~/homeserver-os
```

#### Шаг 5: Начать работу

```bash
# Конфигурация ядра
cd ~/linux-kernel
make defconfig
make menuconfig

# Компиляция (займет 30-60 минут)
make -j$(nproc)
```

## Структура после изоляции

```
Windows (C:\)
├── NewProject\              # Проект (доступен из Windows)
│   ├── linux-kernel/        # Symlink на ядро
│   ├── config/
│   ├── userspace/
│   └── ...
│
└── core\
    └── linux-6.12.28\       # Исходники ядра

WSL2 (Linux)
├── /home/user/
│   ├── homeserver-os/       # Symlink -> /mnt/c/NewProject
│   └── linux-kernel/        # Symlink -> /mnt/c/core/linux-6.12.28
│
└── /mnt/c/                  # Доступ к диску C:\ Windows
    ├── NewProject/
    └── core/
```

## Безопасность

### Что изолировано:
- ✅ Компиляция ядра (в WSL2)
- ✅ Тестирование кода (в WSL2)
- ✅ Сборка образов (в WSL2)
- ✅ Запуск QEMU (в WSL2)

### Что НЕ затронет Windows:
- ✅ Ошибки компиляции
- ✅ Крах тестовой ОС
- ✅ Эксперименты с загрузчиком
- ✅ Модификация файлов проекта

### Что останется в Windows:
- ✅ Исходный код (C:\NewProject, C:\core)
- ✅ Документация
- ✅ Git репозиторий
- ✅ Скрипты

## Альтернатива: Если WSL2 не работает

Если WSL2 не устанавливается или не работает:

1. **VirtualBox** - создать полноценную VM с Ubuntu
2. **Docker Desktop** - использовать контейнеры
3. **Удаленный сервер** - арендовать Linux VPS
